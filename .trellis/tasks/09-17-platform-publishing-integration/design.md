# 平台接入设计草案

## 职责

Azu 管理内容、账号绑定、投稿任务、确认与结果展示。平台适配器将这些请求转换为已有开源工具的调用，并把平台结果转换为稳定的结构。开源运行时作为独立进程运行，不复制其管理后台界面。

```text
Azu 桌面端（账号管理 / 内容详情）
  → Azu 后台（身份绑定 / 投稿任务 / 结果记录）
    → B站适配器 → biliup → B站后台
    → 视频号适配器 → social-auto-upload → 视频号助手
```

当前选型是候选方案，阶段 1 确认依赖版本、许可证及实际接口后才能定稿。平台数据获取方式应如实标注，不把浏览器自动化或网页内部接口称为官方开放平台授权。

## 账号连接

保留当前本地账号 ID。增加独立的连接记录，避免把凭据混入 `content-accounts.json`：

- `accountId`、平台、平台唯一账号标识、平台昵称、最近核验时间。
- 连接状态：未连接、等待扫码、等待手机确认、已连接、已过期、身份不匹配、连接失败。
- 私有凭据引用及运行时版本；浏览器端只接收可展示字段。

本地 `wechat_channels` 映射为 SAU 的 `tencent`。本地 `wechat` 表示微信公众号，不得误接到视频号。B 站使用 `bilibili`。

凭据目录按平台与不可变账号 ID 隔离，使用明确配置的私有持久化路径。不得因服务的 HOME 被 `.lab` 改写而绑定到错误目录，也不自动读取用户默认 Chrome 资料或复制其他项目凭据。

扫码仅建立待验证登录态。读取平台身份并核验绑定后才显示已连接；重新登录到另一个平台身份时，不静默覆盖原绑定。

## 适配契约

建议由共享 TypeScript 契约定义，名称在实施阶段统一：

| 操作 | 返回内容 |
|---|---|
| inspectRuntime | 安装状态、固定版本、平台能力、缺失项 |
| startLogin / pollLogin / cancelLogin | 登录任务、二维码/浏览器入口、状态与需要的用户动作 |
| checkIdentity | 平台唯一身份、昵称、登录有效性、核验时间 |
| prepareSubmission | 账号、视频/封面散列、文案、必填项检查与可审阅预览 |
| submit / saveDraft | 本机任务 ID、阶段事件、平台接受证据；不能只返回布尔成功 |
| reconcile | 已有投稿的作品标识、草稿/审核/发表状态、可用链接与证据 |
| cancel | 是否成功取消、本机资源是否释放、是否可能已提交 |

Python/原生命令通过参数数组与结构化输入调用，不拼接 Shell。使用结构化事件通道区分进度、结果、错误与需要用户操作的状态；原始日志不能作为唯一业务状态来源。

## 发布任务与状态

任务保存 `taskId`、内容 ID 与修订号、账号 ID 与绑定身份、平台、操作类型、素材路径与散列、文案快照、确认摘要、运行时版本、各阶段时间及平台证据。

建议状态：

```text
待检查 → 待确认 → 上传中 → 提交中 → 已提交 → 审核中 → 已发布
                                 ↘ 结果待确认 → 查询核验
审核中 → 审核未通过
提交前 → 已取消 / 执行失败
```

视频号“已保存草稿”单独记录，不能映射为已发布。审核查询无法完成时保留最近确定状态与查询错误，不回退成未发布。

提交前持久化“提交中”及唯一请求标识。提交可能发生后收到超时、崩溃或断网，进入结果待确认，禁止盲目重试。按账号串行执行；用内容、账号、操作及素材快照识别重复点击。

任务存储不得只放内存。进程重启后，提交前中断可恢复为可重新准备状态；提交中断必须先核验平台记录。子进程取消不能被当成平台撤稿。

## 结果来源与迁移

保留已有手动结果，增加 `manual`（手动登记）和 `platform`（平台回读）等明确来源，以及独立核验时间。不得根据手动 URL 自动生成已验证身份或审核通过结论。

把新的平台回读任务、逐账号记录与旧的按平台历史记录建立明确关联。同一作品已由平台标识匹配时避免重复计数；不确定是否重复时展示来源，不猜测合并。新增结构提供版本号与迁移/回滚方案。

## 页面变化

- 账号管理：连接平台、扫码状态、真实昵称与身份、最近核验时间、重新连接、取消连接。
- 内容详情：选择本机视频和封面、填写平台参数、预览、确认提交；视频号可独立选择上传草稿。
- 投稿任务：进度、需要用户操作的提示、取消、查询核验和错误详情。
- 结果展示：明确区分手动记录、平台接受、审核中和已发布。

保留现有页面结构与操作习惯。新图标使用 Lucide（图标库）。不扩展为新的管理系统。

## 2026-09-18 B站连接阶段决策

本阶段直接调用固定 biliup 1.2.4，不安装 SAU 全套 Python 上传依赖。`scripts/bilibili-login.py` 仅负责驱动固定版本的扫码菜单、隔离子进程并输出非敏感事件；后台额外回读 `x/space/myinfo` 确认身份。

连接记录使用有效 dataDir 下的独立私有目录，与原账号 JSON 分离。原始凭据只由后台读取并发送给固定 B 站域名。登录与检查使用单账号文件锁；重新扫码身份不匹配时保留旧凭据。登录连接不打开 externalActionsEnabled 发布开关。

biliup LICENSE/README 表述差异仍未厘清，因此仅作本机运行时安装验证，不把二进制打包进本项目，不宣称商用分发已获确认。真实投稿、作品回读、视频号与定时发布本轮均未开始。
